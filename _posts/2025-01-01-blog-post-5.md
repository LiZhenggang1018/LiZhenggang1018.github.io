# **背景**

## 业界信息

最早常见的手机相机的光圈是固定不可变的，后续开始有主摄配置可变光圈（如下）。

1. 最早的三星Galaxy S10(F1.5 F2.4 两档)，
2. Mate50后大部分Huawei产品（自动切换4档：F1.4 F2.0 F2.8 F4.0 ，专业模式10档）
3. Xiaomi13 Ultra一代（F1.9 F4.0两档）
4. [**苹果iPhone 18 Pro**](https://www.apple.com.cn/iphone-18-pro/) 4档（F1.48 F1.8 F2.8 F4.0）


背景参考：[让光线随心所用！一文读懂智能手机的可变光圈技术！](https://zhuanlan.zhihu.com/p/593743993)
可变光圈对手机相机有较大影响的原因在于：针对用户的一些高频主摄影像场景，如：夜景 、（多景深）多人合影、鲜花、美食、文本、宠物、高亮人工光源banding/频闪、运动抓拍，该器件能够产生（仅靠后处理软件算法很难实现同等效果的)显著成像效果收益。

## 基础知识

参考《应用光学》赵存华著 chapter1 光学系统 光圈/孔径光阑 描述部分（光圈－景深计算公式 等)。
对于F1.4 F2.0 F2.8 F4.0 4档。
其中F1.4是大光圈，进光量最大，景深最浅（类似大光圈的模糊效果）；上述相邻2档间进光量减半(尺寸相差根号2)。（参考：[百度百科](https://link.zhihu.com/?target=https%3A//wapbaike.baidu.com/tashuo/browse/content%3Fid%3Db66f18449b16cd980dfd0022)）

## 影响因素

由上书可知，可变光圈主要影响相机的3块：

1. 进光量：
   1. 一般会在夜景（低亮场景）下大光圈增加进光量；
   2. 很少会在极亮场景下用小光圈减少进光量（可以方便地通过sensor gain值来保证不过曝，（几乎）不需要通过可变光圈）
2. 景深：
   1. 在（多景深）多人合影、鲜花、美食、文本、宠物等对扩展景深有诉求的场景，使用小光圈扩展景深；
   2. 但对于大光圈/虚化人像等对压缩景深/扩大虚化光斑弥散圆尺寸 有诉求的场景，采用大的物理光圈效果并不明显（原因：一般的后处理虚化算法已经演进到相当成熟能够实现媲美单反的模拟虚化效果，与此同时手机相机尺寸有限，即使F1.4的物理大光圈的实际虚化程度也很有限（参考下文详述），无法跟单反相机的F1.4虚化效果相提并论），故大光圈虚化场景并不依赖大物理光圈（采用默认F2.0也可）。
3. 曝光参数：拉长曝光时间可以在一些场景缓解人工光源banding（banding消除主要靠将曝光时间拉长到人工光源能量周期的整数倍（如50Hz正弦波交流电供电人工光源对应的消除banding的相机曝光时间为10ms的整数倍），但一些极限场景下（高亮banding）面临曝光时间无法拉长（此时gain/iso已到极限）否则过曝，此时需要小光圈来减少进光给拉升曝光时间提供余量），缩短曝光时间（大光圈）可以在一些场景（如运动抓拍）去运动模糊、去视频震颤（抓拍拍照模式下，可以（激进地）设置F1.4为默认光圈值）。（另一个舞台直播的高亮banding场景通过ND镜减少曝光量见：[xfold 6发布会手机直播总结](https://wiki.vivo.xyz/link/space/~11193965/content/xfold%206%E5%8F%91%E5%B8%83%E4%BC%9A%E6%89%8B%E6%9C%BA%E7%9B%B4%E6%92%AD%E6%80%BB%E7%BB%93)）

还有一些其他的影响因素，如：

1. 整体成像效果（权衡像差、锐度、解析力等，中等光圈最佳如F2.0）
2. 图像边缘解析力(小光圈下最佳)，
3. 星芒效果（小光圈/不合理的光圈叶片结构对点光源等产生的漂亮的/不真实的星芒）等。

# **切换策略**

实际的用户场景中，上述3块主要因素（+其他因素）会共同（甚至同一时刻共存地）作用于光圈的调节目标，所以整体的光圈智能切换策略要考虑的因素较多，包括：

1. 拍照/视频及其子模式(普通 人像 夜景 大光圈 闪拍/抓拍 专业 三方 高像素，不同模式虽然策略一致但侧重场景/关注收益点不一样的话，阈值参数/默认光圈值/各条件优先级可以不同，典型如：视频录制相比拍照更注重视频去震颤，更强诉求大光圈；高像素拍照对比普通拍照，PerPixel感光面积更小，更强诉求大光圈等)
2. 亮度/AeLv
3. 曝光参数(光圈先定，曝光时间与gain值适配后行，而不是反过来)：ExpoTime（StaggerHdr仅考虑Normal帧曝光时间），gain，是否达到器件极限曝光量
4. 物距（近距下边缘解析力很重要）：激光/AF上报
5. 各类AI场景检测结果：鲜花、美食、宠物、文本、电子屏幕
6. (处于不同对焦面的)人脸识别结果，多人脸框大小、位置（过滤小人脸、边缘人脸、侧脸）、是否为构图主体、是否运动（通过前后帧的人脸框交并比iou与阈值作比较判断人脸是否移动）（剔除（运动的、不处于构图主体的）路人）
7. banding信息 (flicker sensor报值或电子屏幕场景检测结果)（常见正弦波交流电供电的人工光源、以及部分车载系统的DC供电（含高频纹波）的LED屏幕）
8. 运动以及运动降曝光参数（1、消除运动模糊诉求大光圈/短快门时间；2、运动场景下如果发生光圈切换导致的预览丢帧会造成显性的预览卡顿用户体验；）
9. 虚拟光圈(虚化算法强度)
10. 其他各类需特殊处理的corner case
故切换逻辑比较复杂。一般会：

1. 先定义若干独立典型目标场景，
2. 定义各模式各场景准入准出条件、阈值效果参数，默认光圈与目标光圈、优先级（优先级由高到低近似认为：增加进光量 > 去banding > 景深拓展 > 去运动模糊/消视频震颤，但个别场景需单独考虑）等，
3. 然后将光圈的切换逻辑适当简化为若干档位（如4档）的有限状态机FSM（一种基于std::variant实现有限状态机的实现可参考：[Finite State Machine with std::variant](https://link.zhihu.com/?target=https%3A//www.cppstories.com/2023/finite-state-machines-variant-cpp/)），每个目标场景的进入或者退出等价于一个状态转移方程，每个场景/状态转移方程独立计算并最终根据约定的场景优先级进行统筹决策）
4. 同时考虑到各类场景检测结果/辅助器件上报结果时域上并不稳定，为了防止光圈的不同档位来回切换(带来预览丢帧或预览效果跳变)，需：
   1. 针对决策结果进行时域滤波（连续X帧/Y ms满足某条件）（由于预览/检测流上挂载的实时AI场景检测算法出于时域稳定性/实时计算性能要求，每五帧才计算/更新一次场景检测结果，故X=5\*N）；
   2. 进入场景/退出场景的阈值参数做双阈值(进入参数与退出参数不同，两者有一个gap，防止在边缘条件下不断拉风箱进入退出)设计。来保证稳定性。

# **其他问题**

可变光圈还涉及如下问题：
1、光圈的切换，在较短的时间内（硬件能在十几ms/小于一帧帧长时间内 将光圈马达推到位）对相机进光量施加了剧烈变化（F4.0到F1.4有8倍进光量变化），由于用户对连续的相机预览帧的亮度（感知更强）、颜色（感知次之）要求时序上效果一致（否则会出现如亮色跳变/预览闪烁的不好用户体验。）因此光圈变化需与3A（主要是AE）时序上紧密联动（且对于3A在环境变化时的收敛速度有强诉求）。对于(假如有)实在无法保证亮度/效果一致性的预览帧要drop掉（不送显）。当drop帧较多时用户能够在预览界面上（尤其暗场景/帧长较长时拍摄运动物体）明显感知卡顿（由于丢帧导致视频录制过程中不切光圈），故须尽量减少因光圈切换导致的预览丢帧。
2、为了减少光圈切换预览丢帧，有2种方案：

```
1. 3A+ISP与光圈时序紧密配合（实现最终的所有预览帧瞬态/稳态切换效果一致，不需丢帧）；
2. （可能的）可变光圈热启动/热记忆方案（参考AE的热启动/热记忆方案，参考文章：TBD）；
```

这里简述2：热启动/热记忆都是在打开相机起流后出首帧之前（而不是预览已经出图之后）根据一些非图像的（因为此时相机未出图）切换参考信息（一些camera辅助器件）将光圈配置好（仅针对有限的某些切换场景）：

```
1. 热启动：基于RgbSensor/多光谱sensor的lux报值（lux报值与环境亮度aelv（vivo采用luxIndex表征）存在可标定的对数换算关系，均可用于表征环境亮度，可通过灯箱标定获取勒克斯&LV的转换参数）、激光sensor的物距报值（可能flicker sensor的人工光源频闪报值（但是计算可靠banding frequency涉及flicker器件的时域多次采样，耗时较高，在本方案中无法使用））等来基于亮度、物距（可能bandingFrequency）配置出流前首帧光圈，
2. 热记忆：根据时序上相近的、环境亮度变化小（rgbLux值相近）的上次相机停流时刻已经配好的光圈值来配置本次出流前首帧光圈（类似于用户关闭相机后很短时间内再次打开相机，本次起流&上次停流的环境亮度几乎一致&&时序相近，则认为2次拍照出流过程外部环境类似，可直接复用上次光圈值）。
```

上述方案由于起流前就直接配好了目标光圈值，预览（若后续光圈不切换的话）无需丢帧。
本方案软件上存在的难点是：光圈智能切换模块必须要等(另外几个独立的软件模块)辅助器件模块（RgbSensor/Laser/FlickerSensor）上电WarmUp且给出第一个有效准确状态数据后（这个过程可能很慢）才能决策出首帧光圈，之后是AE配置首帧曝光参数+sensor最终出首帧图，但相机从打开到出首帧的时间间隔是一个重要性能（用户强感知）KPI，故热启动、热记忆方案时序上须尽早完成。
可考虑的一种方案是辅助器件提前上电，其流程为：在相机apk最早确认用户打开相机意图的时刻（对应apk界面用户点击相机apk并抬起手离屏后），apk通过HIDL/AIDL下发EarlyCapture指令给HAL，HAL在此阶段异步并发地对（后面相机可能用到的）各辅助器件进行上电WarmUp（一种可能出现的性能问题优化case参考：[用常驻内存换相机启动/运行性能](https://zhuanlan.zhihu.com/p/1930675593118197134)），后续相机想要使用此辅助器件时，join()上述上电thread/co\_await()此上电Coroutine 获取数据即可。
3、光圈切换帧与拍照zsl出帧互斥：拍照算法一般是多帧RAW融合，但不同光圈值的帧（尤其切换前后的相邻几帧）由于景深/3A效果差异导致其多帧RAW域融合效果不佳，拍照算法需求光圈值一致的多帧送融合，可考虑：当点击拍照apk下发CaptureIntent时，

```
1. 若光圈还未开始切换，lock光圈（不允许光圈切换），直至拍照结束后unlock光圈。
2. 若光圈已经在切换过程中，选帧模块选择光圈一致的帧送融合/走单帧拍照。
```

4、大光圈模式下 物理光圈、虚拟光圈UX：两者其实无关，物理光圈指的是真实光圈（可变光圈的实际物理尺寸），虚拟光圈指的是大光圈虚化算法的强度，jpeg的exif字段中光圈值写物理光圈（在没有可变光圈之前，手机exif实际写的是虚拟光圈）。
5、可变光圈与AF/对焦马达的问题：如下2种：

```
1. 当AF未完成对焦时（AFState一些状态枚举表征对焦过程未完成/正在对焦时），（可以）不进行光圈切换，原因：此时可能环境发生了变化（切换可变光圈倾向于参考稳定的环境检测结果），且依赖的AF上报物距（此时可能）不准。
2. （一些场景下）受限于器件供电（或不合理的硬件电路设计），光圈马达与对焦马达（可能）不能同时工作，否则供电不足导致2个马达都推不倒位，即同一时刻只能保证一个马达正常工作。此时在上述（5.1保证了 对焦过程不会切光圈）的基础上，还需保证 切光圈的过程时不会对焦，一种方案是：当智能决策模块要切光圈时，先下发PreSwitch预切换指令（此指令不会执行切光圈而只是预告），AF响应此命令完成对焦+锁焦，待锁焦后再执真正的切换光圈操作。（类似拍照先下发PreCapture等3A收敛+lock 3A,然后下发真正的拍照命令出帧）这么设计的原因是：3A位于相机软件链路的前端/RealTimePipeline，而智能光圈决策位于后端/OfflinePipeline(需要等到出图且图像检测分析算法运行出结果)，前端/AF要（顺流而下地）控制后端/光圈智能切换状态是方便的，而后端状态想要反控前端难以做到实时，可以通过PreSwitch预通知来（预留操作时间）实现反控（另一种是通过注册事件监听异步回调的方法，参考：TBD）。
```

6、器件跌落保护：可变光圈是一个跌落敏感器件，手机如果跌落而此时光圈在某些档位上则极易造成器件损坏。一种方案是：

```
1. 打开相机时，通过Acce+Gyro Sensor（加速度计与陀螺仪）不断监控是否有跌落（一般手机都配置有跌落检测功能以保护手机硬件），有则HAL侧通过event机制（参考：[基于事件Event机制用于 独立C++模块数据通信+优化HAL通路延时](https://wiki.vivo.xyz/content/2056816)）通知驱动（以最高优先级响应）将光圈推到安全档位（整体耗时有较严要求）。
2. 关闭相机时，则由驱动在器件下电前将叶片推至默认安全档位（与之对应的，打开相机时，由驱动将叶片从安全档位推至该相机场景的默认/热启动/热记忆生效档位）。
```

7、器件异常保护：光圈马达（开环/闭环）有可能TargetCode与ActualCode(要推到的目标code值与推完之后的实际code值)并不一致（出现偶发严重硬件故障时，光圈叶片甚至可能卡住），因此每次推马达都需要实时check两者之差是否在合理（根据光圈马达是开环/闭环类型需选取不同的阈值）误差范围，如不在位则需要（最大次数有限的）多推几次并上报器件异常打点。
8、星芒问题：光圈的实际叶片结构工艺限制其孔径光阑并非是理想对称圆形，而是类多边形且有尖锐角边缘的形状，光圈叶片重叠位置边缘的多重衍射现象叠加会导致点光源的PSF退化成含若干尖锐旁瓣的类星芒形式。该现象/问题（也可能非问题，特定场景营销引导得当反而可被宣传为显性的光圈特性，但其实F2.0拍太阳的星芒会很难看）本质要通过优化硬件结构/叶片形状解决（多叶片（如：12或18个叶片的机构要优于6个叶片）近于圆，光轴对称，少锐角）。软件上可做的优化是：检测到一些用户高频容易拍出（且审美不太能接受的）星芒的场景（如 太阳等），检测到该场景（场景亮度超阈值加图像二值化、边缘/圆分割检测提取、gyro辅助判断相机位姿等粗略识别）则提前切换到某一（星芒较弱，如大光圈）光圈档位。

9、LSC问题：不同档位的光圈值/不同的异形孔径光阑对镜头的Lens Shading恶化问题程度不一样， LSC模块在某些档位（如小光圈）并不能完全矫正此问题。导致在拍摄纯白如白纸、白墙、白桌（购机用户在手机专卖店的高频取景case，需重点关注）等物品时有明显不同色块（白色时用户对此问题感知最强），一种（可能）的规避方法是：识别此纯色场景（通过AWB模块上报的环境色温K值），据此来选取Lens Shading恶化程度较小的光圈档位。（参考：[关于可变光圈Camera的Shading校正方案的思考](https://zhuanlan.zhihu.com/p/652355631)）
10、AF问题：当AF在预览上已完成对焦后，光圈又从小光圈切到了大光圈，相当于从大景深切到了小景深，（可能）导致原来状态为准焦的对焦区域，由于景深变浅变为不准焦。此时AF（可选地）可根据此场景决定是否再次触发对焦。
11、专业模式拍照视频：类似3A，可变光圈在此模式下也有Auto/自动跟Manual/手动两种。自动模式（可以）仅判断环境亮度做低高亮的（最基础的）光圈F1.4/F2.0自动切换（此时光圈不支持被联动调节，即快门优先/iso优先时不通过自动调节光圈来保持亮度不变）。 手动模式（光圈优先）则由用户自动选择10档中的某一档（不支持光圈智能切换）。
12、其他：

```
1. 当主摄在工作但非送显路时（主摄作为辅路在工作，此时是广角/长焦送显作为主路），（可以）不进行光圈的切换（因为对辅路的图像画质要求没有那么高，且可变光圈硬件一般只配置在主摄，广角长焦没有，但光圈智能切换依赖的图像AI检测算法识别的是从主路/送显路的预览流fork出来然后downscale的camera图像（即FD流），主辅路的图像内容（如fov等）并不一致无法作为指导主摄光圈切换的有效判据）。（注：VIVO在高通平台SAT场景下，主辅路都有FD流，而友商仅主路有FD流、辅路无FD流（省功耗）。）
2. 闪光灯拍照时：闪光灯状态选择：总是打闪&自动打闪时（有预闪、强闪的剧烈环境亮度变化时），确保光圈不自动切换（因为场景不稳定）；不打闪&闪光灯常亮（环境亮度稳定），光圈正常切换；
3. 由于推可变光圈非高功耗操作且切换并不频繁，无需对光圈智能切换模块做热逃生（手机温度到达一定上限因温控策略需关闭部分软件算法功能）方案。
```

# **备注**

1、为何手机F1.4大光圈不能产生（类似全画幅相机F1.4大光圈）的虚化效果？

根因：虚化光斑大小（表11行）与**焦距（表5行）的平方**成正比，焦距的影响更大，而手机焦距更小，同等F数手机相机的光斑占传感器比例更小（表第12行）

如下表格示例 对比：

F1.4手机相机的光圈 约等于 F3.8全画幅24mm焦距相机 的虚化能力，这个虚化能力远弱于F1.4全画幅24mm焦距相机。
