# **背景介绍：**

手机拍照一般采用RAW域多帧AI网络融合降噪&HDR算法（RAW域： MFNR Multi Frame Noise Reduction， MFHDR Multi Frame High Dynamic Range）

多帧参考：[《understanding the in camera rendering pipeline and the role of ai deep learning\_ICCV2023》](https://wiki.vivo.xyz/content/2056825)  P218  ISPs with multi-frame (burst) imaging 章

一般拍照流程为：

1. HAL（VCF）根据（后处理算法需求的）出帧策略出（从ZSLBuffer中选取）多帧（可能含不同曝光量的）RAW图（如7\~9帧）
2. 多帧RAW送给多帧RAW域处理的后处理拍照算法
3. 拍照算法先将多帧融合成一张高质量RAW图
4. RAW（通过平台侧离线isp接口raw2rgb）转RGB，RGB域算法处理
5. RGB（通过平台侧离线isp接口rgb2yuv）转YUV，YUV域算法处理
6. 最终处理的YUV送上层APK，随exif等做JPEG/HEIF编码存盘

多帧RAW域处理的后处理拍照算法可实现从原始Raw图转换到Yuv图，并具有去除Raw图的噪声，提升图像细节，提升动态范围等功能。

拍照算法整体流程分为：

1. 前处理
2. 检测&分割
3. AI网络融合
4. RGB域处理
5. YUV域处理

本文主要介绍拍照算法的前处理模块中的图像配准算法，包含：多帧raw收集、解压、校验、参考帧选择、灰度化、配准、H矩阵(传导)计算、warp， 并基于此介绍基于C++26 std::execution将前处理模块做结构化并发的框架。

# 配准定义：

通俗定义：给定两幅图像I1, I2，图像配准算法的目标是找到一种变换T: Ω1 -> Ω2, 使得变换某一图后两幅图像的相似程度达到最大。

视觉领域的基础算法，只要涉及多输入问题，就有配准。

相机领域中的配准：

1. 为图像融合算法（多帧降噪MFNR、多帧HDR、多摄大小FOV融合）提供辅助帧往参考帧上对齐的功能，使融合算法能更多利用参考帧图像内容，实现全局/局部清晰度、对比度效果提升。
2. 防抖功能中，为了视频效果减少拍摄设备带来的抖动感，将当前帧的图像内容对齐到运动轨迹平滑后的当前帧位置。
3. 相机拍照时，为解决sensor行曝光和rolling shutter带来的图像形变(LDC: Lens Distortion Correction)，对当前图像做图像校正的功能。
4. 基于RGB（or RGBD Depth）相机的3D建模、SLAM中tracking模块、基于视差&三角测量法的双目深度估计等。

# 正常拍照下的多帧配准

(S: short expo, N: normal expo, L: long expo, E/ES: Extreme short expo, 指代不同曝光序列的zsl出帧)

点击拍照时，HAL会根据后处理拍照算法的需求，从ZSL队列抓多帧RAW图。HAL出的多帧序列一般保证：

1. 首帧为N帧（一般首帧为参考帧）
2. L帧在最后（目的：L帧一般expoT>=40ms，L帧放最后可以减少网络融合中多个N帧之间的帧间隔）

典型出帧如：

1. HDR                        极暗场景 NSNSNL
2. NormalDR          低iso亮场景 NNNNNN
3. NormalDR 高iso暗+极暗场景 NNNNNL

先对参考帧与待配准帧做如下预处理：
1. Unpack：收集所有帧，做unpack：压缩raw（各类芯片厂商自定义的、用于节省内存空间的一类内部高效传输的压缩RAW格式）转非压缩raw
2. Substract Green pixel：待配准帧和参考帧分别对raw图抽取2个G通道取均值（由于一般配准只需要灰度图，所以这里简化为针对raw图根据不同BayerPattern（RGGB RYYB GRBR BGGR GBRG…）仅抽取对应G/Y像素，类似传统配准流程的灰度化）。
3. Downscale：下采样到1/4尺寸（1/2w\*1/2h）。
4. Brightness Align：待配准帧（待配准帧一般含变曝光帧S L；S与L的变曝光帧相对于N帧亮度不一致，而N帧与N帧的则亮度认为已对齐(可以额外校验待配准N帧的曝光量是否与参考帧N帧是否一致)）做亮度对齐（根据待配准与参考帧的metadata中的iso expoT算出曝光量之比，乘到全图上），保证变曝光帧与N帧亮度一致。
5. Gama Transfer：gamma变换将图像提亮（因为RAW图本身很暗，按照I= I^0.45提亮）
6. Gaussian Filter：基于5\*5的高斯滤波核做中等平滑去噪（使用 σ=1.0 计算并归一化后的 5x5 高斯核，后续Shi-Tomasi角点检测（or梯度检测）对噪声敏感，需求高斯平滑预处理来保证特征检测重复率（Repeatability），高斯滤波器是唯一的可分离的圆对称滤波器。）
7. 角点检测 +RotatedBRIEF描述符计算：参考帧与待配准帧做完预处理后，再分别进行角点检测。
   * 整体流程可参考：

     * 《[计算机视觉:算法与应用](https://wiki.vivo.xyz/content/2056825)》第一版 chapter6
     * 《[视觉SLAM14讲](https://wiki.vivo.xyz/content/2056825)》chapter7。
   * 考虑采用Shi-Tomasi 角点检测算法（[《good features to track》](https://ieeexplore.ieee.org/document/323794) 以及 [cv2.goodFeaturesToTrack()](https://opencv24-python-tutorials.readthedocs.io/en/latest/py_tutorials/py_feature2d/py_shi_tomasi/py_shi_tomasi.html)），Shi-Tomasi 在Harris 角点检测算法（满足平移、旋转不变性，注意：不满足尺寸/缩放不变性）的基础上进行了优化，改进了角点响应函数（RHarris=det(M)−k⋅(trace(M))2  修改为 RShi-Tomasi=min(λ1,λ2)），以结构张量/自相关矩阵的最小特征值作为响应函数，实现了更鲁棒、参数更直观的角点检测。
   *
   * 图像分块检测：将参考帧分成大小相同的M\*M个块（M典型值16），在每个块里检测最多3个角点，保证每个角点之间横向和纵向距离最小为11（NMS/Non Maximum Suppression筛选出稳健且分布均匀的角点）。

     * tomasi角点 转换成 KeyPoint（octave == 0 ；size == 1.0； 在原图；无尺寸不变性）。
     * 通过灰度质心法计算质心方向，为角点添加角度/方向信息（旋转不变性）。
     * 按主方向反向旋转；双线性插值得到亚像素坐标点灰度值；比较256点对得到二进制描述符；最终得到RotatedBRIEF描述符。
     * 从配置中读配准阈值参数，不同iso下配准结果是否有效的校验阈值是不一样的（iso低，画面亮，对配准点的匹配要求就高，反之则要求低）
     * 根据不同帧类型，校验一些参数如lv iso等，校验帧是否有效，无效的帧需要丢掉（比如待配准的Normal帧，如果相对于参考帧Normal帧 LV iso变化较大，也不参与配准），拦截一些不需要配准的异常情况
     *

     ```
         - [harris角点计算流程+代码+在线演示demo](https://www.ipol.im/pub/art/2018/229/)
     ```
     1. 特征匹配
        1. 特征匹配：对2张图的RotatedBRIEF描述符，计算特征符汉明距离，通过 KNN+RatioTest匹配 寻找最佳匹配点。
        2. Ransac剔除异常点对、保留内点集：采用Ransac的方式迭代剔除异常的特征点对（最小二乘法对外点敏感而RANSAC无此问题），每次迭代随机不重复选取四对不共线的特征点对计算单应性矩阵，利用其对特征点进行warp并计算warp后特征点对的欧氏距离，小于阈值的认为是高置信度的内点，取内点数最大的情况进行后续迭代操作。RANSAC目的是找到最优的参数矩阵使得满足该矩阵的数据点个数最多，通常令h8==1来归一化矩阵。由于单应性矩阵有8个未知参数，至少需要8个线性方程求解，对应到点位置信息上，一组点对可以列出两个方程，则至少包含4组匹配点对（且任意3点不共线）。
        3. H矩阵求解：利用全部内点算出最终的单应性矩阵（H矩阵）
     2. 校验配准结果：校验H矩阵的元素值，如平移、旋转、缩放等参数，是否在阈值范围中。如平移<N pixel,如超过则认为图像偏移量较大丢掉配准帧，如果配准的特征点对总数<10认为配准失败。
        * 原因：拍照场景下想要多帧融合算法取得较好效果，要求用户拍照出帧期间持稳相机，此时帧间H矩阵的旋转、平移、缩放等位移量也相对较小才是目标场景。若位移较大，虽然最终可能也能warp成功但融合效果不及前者。故舍弃部分后者（帧间位移大的）场景对应的帧。
        * H矩阵（3\*3）如下所示，
          * h0 h1 h2
          * h3 h4 h5
          * h6 h7 h8
        * 其中 0134 为旋转，25为平移，67为缩放，h8==1（归一化）
        * 工程经验值（json文件（根据不同场景如亮暗）配置客制化值）。
          1. abs(h0-1) || abs(h4-1) > threshRotate（0.0X）对应旋转超过阈值
          2. h2 || h5 > threshShift（X0） 对应平移超过阈值X0（几十）个像素
          3. h6 || h7 > threshZoom（0.000X）对应缩放超过阈值
        * 当上述任意一个值超过阈值时，认为两帧图像间位移量较大，丢掉待配准帧（该帧不需要warp到参考帧，也不再参与后续多帧融合）。
     3. 配准帧做warp：通过映射矩阵将待配准帧映射warp到参考帧坐标系。
     4. 融合：最终将配准后的多帧送网络进行（特定融合权重策略的）融合。

     在一些变曝光出帧场景下，配准逻辑还需要考虑如下：
在StaggerHDR场景下，（Stagger出的）N帧后面紧跟（Stagger出的）的S帧，Stagger sensor器件在硬件上保证了N帧与S帧的间隔极短（sensor几乎是同时曝光出NS帧），故认为S与N已经是图像对齐，无需做软件配准，S的H矩阵直接赋值单位阵。

1. 存在S帧时，后续所有E都以S帧为参考帧配准（原因：E(Extreme Short，极短曝光)与S的亮度差异< ES与N的差异，亮度差异小的两帧更易配准成功，且S帧相对于N帧曝光时间短，运动模糊更少，更适合作为配准参考帧）
2. 没有S帧，比如NNEEL，（时序上出现的）第一个E和参考帧的N去配准，后续所有的E和第一个E配准
3. N帧与L帧的配准相对简单，没有特殊处理。
4. 普通拍照场景下（非EDOF下）很少使用传导配准（即参考帧帧号一直在变化而非固定某一帧为参考帧的配准策略），这是因为如果使用传导配准，参考帧帧号一直变，会不断对变化的参考帧提取特征点，这样计算会更慢。

简而言之，变曝光的额外的配准逻辑是：直接将短帧与N帧做配准很容易失败，因此：待配准的短帧与短帧参考帧做配准更好；选择短帧参考帧时，如果有StagHDR的S帧就直接用S帧作为短参考帧（因为Stagger的N帧与S帧天然对齐），否则就用最早的（离Normal参考帧时间最近的）E帧作为短参考帧。

手机一般同时也存在硬件配准模块，由离线ISP接口提供，与软件配准的主要区别是：

1. 硬件配准会将图像做更小尺寸的下采样，使用特征检测是简化版的SIFT，而且一些耗时软件运算做了硬化，但效果在某些场景实测下来（可能）没有软件配准好。
2. 对于极暗场景，LV小于一定阈值，使用软件配准，效果（可能）更好。

一些配准容易出问题的场景：

1. 前后景（不共面的特征点）无法同时配准：从算法原理上，求解**单应矩阵H**的理论前提比求解**本质矩阵E**或**基础矩阵F**的要求更严格，单应矩阵除了**对极几何约束**外还要求所有**3D特征点共面**，而本质矩阵或基础矩阵无此要求。单应矩阵H的物理公式由**相机内参K**、**相机外参(R t)**、**特征点所在平面法向量（n）**这3块构成（如下，参考视觉SLAM十四讲 chapter7.3.3 ），故不同平面上的特征点无法用同一套H矩阵配准）这里一般优先保证前景所在平面。


1. 过曝（常见于L帧）帧背景特征点少，
2. 特征纹理少的场景，如夕阳 月亮等。
3. 存在运动目标时（尤其是不同曝光帧间存在运动）配准失败。
4. 高iso场景(9600<iso<=12800) 在极暗场景下，通常会调高iso来提高感光度，但同时也会对噪声更敏感，入图质量很差，对(尤其是ORB-KLT的全局）配准不友好。

## EDOF配准逻辑：

长焦微距拍照模式，由于长焦微距镜头的景深较浅导致前后景不清晰，使用EDOF/多帧融合景深拓展算法，来融合不同对焦距离/景深的N帧，进而保证成片前后景清晰，但EDOF的出帧策略及配准逻辑与一般普通拍照略有不同。如下所示：


EDOF场景下，出7\~9个N帧（不涉及变曝光帧，出帧过程中不断推对焦马达往前景和后景对焦），其中所有帧的对焦马达vcmCode/对焦距离均不相同（一般是0（数字表示出帧帧号）对应当前(预览界面对焦位置帧)，1、2帧对应前景，3\~6或者3\~8对应后景），其配准逻辑为：

1. 第N帧做配准时，选取的参考帧是在[0, N-1]帧中选取abs(cur\_vcmCode – ref\_vcmCode)最小的帧作为参考帧（即取vmcCode最接近、对焦面最相近的历史帧作为参考帧）；
2. 由于参考帧在变化，计算完H矩阵（表征的是待配准帧相对于不断变化的参考帧的位姿变化）后需要做传导计算，将H矩阵归一到相对于同一帧（一般是第0帧）
3. 如果第N帧配准失败，由于H矩阵的传导特性，则后续[N, MAX]帧的H矩阵也认为无效，只送[0, N-1]帧到后续的warp与多帧融合，[N, MAX]帧drop不再往后送。

## HDR配准融合

利用正常曝光、长曝光、短曝光三张图片进行图像配准、鬼影消除、图像融合后得到高动态图片。

对于同一场景不同时间拍的两张相同曝光时间的图像，场景中的运动物体是通过分析两张图像亮度差异进行检测的：静止的场景差异小，运动的场景差异大。主要分以下步骤进行：

1. 亮度对齐：消除三张图像由于曝光差异导致的亮度差异；
2. 粗略运动检测：进行粗阈值分割，最大化运动检测的准确率，忽略漏检率；
3. 精细运动检测：进行精检测，最小化漏检率，在此基础上尽可能降低误检率；
4. 过曝区域检测及重叠区域计算：计算过曝区域与粗运动检测结果的重叠度；
5. 优化：剔除误检区域；
6. 运动校正：对低曝光和高曝光图像中的运动物体进行矫正，矫正后低曝光和高曝光图像的运动物体运动位置与中曝光相同，但是物体的灰度仍保持各自场景中相应物体的原亮度；

整体策略与输出：根据低、高曝光图像的运动情况：

1. 若存在运动区域则不采用相应的图像，仅利用剩下的图像进行HDR合成处理。
2. 若低、高曝光均存在运动区域，则利用Local Contrast算法尽可能恢复图像中的暗区和亮区。

    //    OutputArray dst, // 输出的 6 通道浮点图像，每个像素存储特征值与特征向量。
    //    int blockSize, // 邻域求和窗口大小（类比 Harris 中的窗口）。只取奇数，例如 3、5。
    //    int ksize, // Sobel 算子的孔径大小，用于计算图像一阶导数。必须为奇数，如 3、5、7。
    //    int borderType = BORDER_DEFAULT // 边界填充方式
    //);
    cv::cornerEigenValsAndVecs(gray, eigen, 3, 3);

    std::vector<cv::Mat> channels(6);
    cv::split(eigen, channels);
    cv::Mat lambda1 = channels[0]; // 较大特征值lambda_1，float类型
    cv::Mat lambda2 = channels[1]; // 较小特征值lambda_2

    // 归一化到 0~255
    cv::normalize(lambda1, lambda1, 0, 255, cv::NORM_MINMAX);
    cv::normalize(lambda2, lambda2, 0, 255, cv::NORM_MINMAX);
    lambda1.convertTo(lambda1, CV_8U);
    lambda2.convertTo(lambda2, CV_8U);

    // 显示：使用 fitToScreen 限制显示尺寸
    cv::imshow("Lambda1", fitToScreen(lambda1, 800));
    cv::imshow("Lambda2", fitToScreen(lambda2, 800));

    // Shi-Tomasi 角点二值图
    // 直接使用两个特征值中较小的那个作为角点强度。一个像素只有在两个方向上都存在显著变化（两个特征值都足够大）时才被认为是角点，而最小特征值恰好能衡量“较弱方向的变化量”。
    // 前面 已将lambda2线性映射到 [0, 255]，最强的角点响应变为 255，最弱的变为 0。故下面取选择最强角点响应的 1% （0.01 * 255）作为阈值。
    cv::Mat corners;
    cv::threshold(lambda2, corners, 0.01 * 255, 255, cv::THRESH_BINARY);
    // 其实等价于cv::goodFeaturesToTrack(gray, corners, maxCorners, qualityLevel, minDistance); // qualityLevel 即我们上面设置的0.01，
    // 当然goodFeaturesToTrack()额外做了非极大值抑制，而我们没有，故因此可能在角点附近产生多个相邻响应。
    cv::imshow("Shi-Tomasi corners", fitToScreen(corners, 800));

    // 特征向量方向图
    cv::Mat rgb;
    cv::cvtColor(gray, rgb, cv::COLOR_GRAY2BGR);
    for (int y = 0; y < eigen.rows; y += 10) {
        for (int x = 0; x < eigen.cols; x += 10) {
            const float* p = eigen.ptr<float>(y, x);
            float v2x = p[4], v2y = p[5];
            cv::Point pt(x, y);
            cv::line(rgb, pt, pt + cv::Point(v2x * 5, v2y * 5),
                cv::Scalar(0, 255, 0), 1);
        }
    }
    cv::imshow("Eigenvectors", fitToScreen(rgb, 800));

    cv::waitKey(0);
    return 0;
}
