# 性能优化措施

## 特性方案

结合相机业务本身，提供软件特性方案、软件基础设施来优化性能。

1. [**分段式拍照&视频**](https://wiki.vivo.xyz/content/2056809)：后处理软件与相机实时出图 功能解耦&时域分离。
2. **内存池**方案：优化malloc()等申请内存性能（更快、更可扩展、更少内存碎片问题）(启动时预分配，热路径禁止 `malloc/new`，自定义 allocator / pool)
3. [**结构化并发**](https://wiki.vivo.xyz/content/2056815)方案：std::execution将所有任务拆分依赖关系，尽可能所有模块做并发。
4. 通过[**事件Event机制**](https://wiki.vivo.xyz/content/2056816)（发送者发送消息，接收者注册监听异步回调接收消息触发回调）优化通路延时的事件Event机制。
5. [**阻塞队列**](https://smartgit.vivo.xyz/gerrit/#/c/13392167/1/camx/vivoutils/DoubleEndedBlockingQueue.h)：生产者-消费者模型中复用资源，避免频繁创建申请资源（如内存）。（安卓BufferQueue）
6. [**线程池**](https://smartgit.vivo.xyz/gerrit/#/c/13669120/2/camx/vivoutils/MsgQueue/MsgQueue.h)：避免频繁创建线程（new std::thread）的开销，复用线程资源。ThreadPool(size\_t threads = std::thread::hardware\_concurrency())，工作窃取（Work Stealing）保证负载均衡。
7. [**dlopen中Linux全局锁的性能优化**](https://zhuanlan.zhihu.com/p/1930675593118197134)，通过static关键字延伸变量声明周期，以常驻内存换启动性能。

## 编译优化

1. 编译选项**-O3**（比常用略激进，推荐）/ **-O2**（常用，推荐）。部分场景考虑**-Ofast**（比-O3更激进，启用**-ffast-math**会加速浮点数计算但浮点数精度有微小差异，对浮点数精度要求高场景谨慎使用）

Ofast > O3 > O2 > O1 > O0

明确哪些优化编译器在打开优化选项时会自动帮程序员做（如：变乘法操作为移位&加法的混合，提取公共表达式，for循环的逐元素赋零改成memset\_s清零、循环展开-funroll-loops等），不需要自行手动优化（[https://godbolt.org](https://godbolt.org/) 查看编译优化结果）。

1. inline内联：
   1. LOCAL\_CFLAGS += **-O3 -finline-functions -finline-small-functions**
   2. **attribute((always\_inline))**提示内联，
   3. **attribute((noinline))**防止意外内联
   4. （虚函数会禁止内联，这是虚函数主要性能开销点而非虚表）
2. **-ftree-vectorize**：启用编译器的自动向量化，分析并将代码中的循环等结构转成SIMD指令的向量化代码。（-O3默认开启）
3. 分支预测帮助编译器执行分支优化：
   1. **[likely](likely) [unlikely](unlikely) **（C++20）修饰分支/代码块。
   2. **builtin\_expect(!!(x), 1) builtin\_expect(!!(x), 0) ** (C++20之前)
   3. **attribute((hot))和attribute((cold))**修饰函数声明标记整个函数的调用频率。
   4. **[assume](assume)** （C++23）条件假设承诺（程序执行到此处时表达式必为真）,消除不可能分支。
4. 编译期计算，部分计算运行时上移到编译时（声明**constexpr**变量/函数，**constinit,consteval, if constexpr()**）
5. **禁用volatile**：volatile关键字会禁止编译器优化\\重排，基本上别用（很多时候起不到线程安全的目的，线程安全用atomic保证）。
6. 编译项中关闭部分有开销的特性，如：
   1. 关闭异常exception，**-fno-exceptions**
   2. 关闭RTTI编译项。**-fno-rtti**（坏处：依赖RTTI的C++标准特性（typeid()、type\_info（）**、**dynamic\_cast（））缺失）
7. PGO（Profile-Guided Optimization，配置文件引导优化）：基于运行时数据的编译器优化技术，通过收集程序在实际运行中的行为数据来指导编译器做出更精准的优化决策（内联、分支预测、代码布局等）。
8. LTO链接时优化：**-flto**
9. 特定CPU专属定制、不可移植的优化：
   1. **-march=native** ：探测CPU支持的指令集并优化
   2. **-mtune=native**：针对CPU的微架构做性能调优。
10. 代码添加关键字帮助编译器做优化
    1. **noexcept**承诺不抛异常：让标准库敢用移动代替拷贝，编译器更敢内联。
       1. 给自定义类型的移动构造/赋值、swap 加上 noexcept，可以显著提升 vector、deque 等容器扩容时的性能。（标准库的策略是：若移动构造函数标记为 noexcept，则用移动；否则改用拷贝，即使拷贝更慢。）
    2. **\_\_restrict**：保证指针不别名，解锁自动向量化：**\_\_restrict **或 **restrict**承诺此指针所指向的内存，只由该指针访问，不与任何其他指针重叠。编译器可以：
       1. 将循环向量化，用 SIMD 指令并行处理。
       2. 重排指令，软件流水线，大幅提升吞吐量。
    3. **final**：干掉虚表跳转，直接内联：final用于声明类不可被继承/虚函数不可被override，可以消除间接调用（devirtualization），直接跳到具体函数实现，甚至将该函数体完全内联到调用点。

注：参考吴咏炜老师培训课程[《C++性能优化》](https://github.com/TheSeanParker/Wu-Yongwei_Boolan)
## 代码优化

1. 循环优化：只做最必要的，不做非必须的（声明/构造变量，无用的重复计算）
2. 循环展开Loop Unrolling：将循环体复制多次，每次迭代执行更多工作，从而减少循环分支判断次数。如：for里面同时做4个数据的处理，然后每次跳4个数据（Cache友好）（-O2编译器会自动优化）
3. 移动语义避免拷贝/copy elision，函数参数传递与返回时注意对象传递方式，典型如：
   1. std::**string\_view**（某些场景）代替std::string作为函数形参。（不涉及元素所有权时）用视图**view**（或std::**span**）替代容器来传参。（C++20）
   2. 函数输出数值时，使用返回值而非输出参数。（编译器保证**RVO**/Return Value Optimise, **URVO**/ Unnamed Return Value Optimise，没有不必要拷贝）。

## 多线程优化

1. 锁的颗粒度（只保护必要的数据竞争条件下的临界区共享数据），不在锁中调用未知的回调。
2. atomic替代锁，lock-free programming。（但情况复杂时，由于编译器会在保证结果不变的情况下自由地乱序调整，消除中间变量等，加锁会更简单可靠）
3. std::shared\_mutex等共享锁（区分读写case，多个读操作不互斥）替代简单锁std::mutex
4. thread\_local线程本地变量（避免在多个线程之间共享数据）

## 容器优化

1. C++标准库容器类型选择（是否随机访问，是否首/任意/尾需插入/删除，是否排序，是否键唯一，缓存友好性，LIFO/FIFO）(CppCon中有测试文章表示vector总是好)
2. **emplace\_back**(arg)（有时候）替换push\_back(Obj(arg))
3. 用**reserve**来保留大小，减少内存动态分配。
4. 选择合适的算法和数据结构（复杂度优化）

## 内存管理&内存池

**PMR**：多态内存资源 (Polymorphic Memory Resources) ：C++标准库中提供的高性能（优化后的STL标准库实现[3.5x faster](https://www.youtube.com/watch?v=q6A7cKFXjY0)）的预定义内存资源分配策略。它提供了一种标准化、可扩展的内存管理框架，可高效实现**内存池**功能。(在关键路径上避免反复申请/释放堆内存。)

1. 多线程[**synchronized\_pool\_resource**](https://en.cppreference.com/w/cpp/memory/synchronized_pool_resource.html)
2. 单线程 [**unsynchronized\_pool\_resource**](https://en.cppreference.com/w/cpp/memory/unsynchronized_pool_resource.html)

参考《[C++17 - The Complete Guide](https://www.josuttis.com/welcomee.html)》

## 缓存友好性

优化内存访问、提高缓存命中率：

1. 顺序内存访问：如行优先遍历(访问内存时尽量顺序访问，避免随机访问。相关联/易被一起访问的数据尽量放一起/紧凑排布)
2. 声明结构体时，用位字段压缩数据，成员按大小递减的顺序声明减少padding。
3. 消除多线程中的伪共享（两个不同的处理器修改位于同一缓存行上的不同变量时）问题：
   1. 多线程共享的数据 声明 **alignas(std::hardware\_destructive\_interference\_size) **对齐/填充内存对象。
   2. 用局部变量替代多线程共享的数据 消除数据竞争
4. 冷热数据分区，冷热数据使用不同的内存分配器，热数据尽量排布在一起共享缓存行。
5. 内存预取Pre-fetch，指令预加载。

## 文件IO

1. 异步IO替代同步IO：io\_uring&lib\_uring
2. 压缩数据：zlib，图像视频文件的编解码软硬件算法（MediaCodec、libjpeg\_turbo）。
3. 共享内存方案：DMA 、Gralloc、 ION 、Ashmem等共享内存规避不同进程间通信或不同设备间通信的内存拷贝。

## 优化so大小

1. 优化代码大小：**-Os**（比-O2保守，关注的是产生最小so文件）；**-Oz** 更激进
2. 导出符号可见性控制：
   1. .mk文件声明默认不导出**-fvisibility=hidden**
   2. .h/.cpp文件中**attribute((visibility("default")))**定向导出符号
   3. 使用版本脚本精确控制导出符号。
3. 链接器移除未使用的代码：**-ffunction-sections -fdata-sections**
4. 编译时去除符号信息（等同于strip）：**-s -DNDEBUG**
5. 涉及模板时，[**thin-template**](https://github.com/xiaoweiChen/Cpp-Templates-2nd)用于减少模板代码膨胀（将模板的公共部分提取到非模板基类中，减少模板实例化产生的冗余代码量）。
6. **EBO**（Empty Base Optimization）空基类优化、**[no\_unique\_address](no_unique_address) ** 等（C++20）

# 优化原则

1. 测量优先：先profiling，找到瓶颈，再优化热点。（"过早优化是万恶之源"）
2. 80/20法则：80%的时间花在20%的代码上（阿姆达尔定律Amdahl's Law，系统优化中"短板效应"的本质）
