# 《Profiles_for_Simplicity_and_Guarantees》By Bjarne Stroustrup

profile

- 一组关于理想特性的一致保证
- 通过静态分析与运行时检查相结合的方式来强制执行
- 对数十年来各类技术（如编程准则、静态分析、运行时断言、不变式等）的综合运用
- 目标：实现完整的类型安全与资源安全

展示用profile来实现：

- 每个对象在使用前均已初始化
- 不通过悬空指针进行访问

初始化规范（Initialization Profile）概要

• 对象在使用前必须经过初始化

• 在其内存被再次使用前，对象必须经过销毁

• 初始化规范属性

• **\[\[uninit\]\]**：对象在使用前必须进行初始化

• **\[\[ref_to_uninit\]\]**：必须指向一个 \[\[uninit\]\] 对象

• **\[\[must_init\]\]**：一种必须被初始化的 \[\[ref_to_uninit\]\]

• 属性标注在所修饰名称之后

• 对 **\[\[ref_to_uninit\]\]** 进行类型转换（cast）后，结果仍为 \[\[ref_to_uninit\]\]

• 用于标识此前未初始化的内存现已完成初始化的函数

• \`T\* **now_init**(T\* p \[\[ref_to_uninit\]\]);\`：断言 \`\*p\` 已完成初始化

• \`T\* **now_uninit** \[\[ref_to_uninit\]\] (T\* p);\`：断言 \`\*p\` 现处于未初始化状态

• 命名空间作用域内的静态对象（namespace static）必须在编译期或链接期完成初始化

• 运行时零开销（完全通过静态分析强制执行）

保证初始化&保证不做初始化

\[\[profiles::enforce(std::init)\]\];

X x; // x 必须初始化。（若x是全局变量，则X x;会做静态变量初始化 编译Ok；若x是局部变量，则X x;编译报错）

X y \[\[uninit\]\];// y必须不做初始化

int m2 = y.m; // 由于y没有初始化，这里m2也会编译报错。

延时初始化

X x \[\[uninit\]\];

X y = z;

construct_at(&x,z); // OK, 执行后，x 不再处于未初始化状态

construct_at(&y,z2); // Error: 重复初始化

传递未初始化的内存(指向未初始化内存的指针)

void f(X\* p \[\[ref_to_uninit\]\]); // p 必须指向未初始化的对象

void g(X\* p); // p 必须指向已初始化的对象

void tst()

{

X x \[\[uninit\]\];

f(&x);

g(&x); // 错误

X y = 7;

f(&y); // 错误

g(&y);

}

保证不会通过"悬空指针"（dangling pointer）进行访问

容器中的元素如果relocate了，则原生指针会失效（vec.push_back()后之前保存的vec的迭代器就失效了）

失效分析概要

若已获取容器内某个元素的指针，则不能调用会导致该容器失效的函数

非const 函数被视为会导致失效

const 函数不会导致失效

函数被视为会导致其非 const 参数失效

函数不会导致其 const 参数失效

失效分析属性

**\[\[not_invalidating\]\]**：该参数不会被当前函数导致失效

**\[\[owner\]\]**：该指针必须被释放（delete）或传递给其他所有者

属性总是出现在其所修饰的名称之后

用于断言参数不包含悬空指针（dangling pointer）的函数

**no_dangling()**：一种内置函数

Widget inner(Window& window)

{

Logger log;

WidgetFactory factory{window, log}; // factory 持有指向 window 和 log 的指针

return **no_dangling**(factory.create_widget()); // 所创建的 widget 并不依赖于 &log这个局部变量的指针。

// no_dangling() 在没有证明的情况下断言：不会出现悬空指针。这属于对"失效分析（invalidation profile）"的局部抑制。

// 如果不加**no_dangling**，则上述代码会在启用profile检查时失效

}

在更高层级，我们使用所有权抽象（RAII）；

在低层级，我们标记持所有权的（一般是旧的C风格库）指针**\[\[owner\]\]**

使用 **\[\[owner\]\]** 来明确资源句柄的实现方式，防止资源泄漏

class Int_vec {

int\* elem **\[\[owner\]\];**

int sz;

public:

int_vec(int s) : elem{new int\[s\]}, sz{s} {}

~int_vec() { delete\[\] elem; }

}

\[\[owner\]\] 规则

\[\[owner\]\] 必须被销毁或转移给另一个 \[\[owner\]\]

非 \[\[owner\]\] 不得被销毁

将 \[\[owner\]\] 赋值给非 \[\[owner\]\] 会产生别名（alias）

将 \[\[owner\]\] 赋值给另一个 \[\[owner\]\] 会转移销毁责任，并留下一个非 \[\[owner\]\]

void use(int\* p, int\* q **\[\[owner\]\]**)

{

// …

delete p; // **error: not owner**

delete q; // **required**

}

void f()

{

int\* p = new int{7}; // **error: throws away \[\[owner\]\] attribute**

int\* q **\[\[owner\]\]** \= new int{7};

use(p,q);

\*p = 7;

delete q; // **error: \[\[ovner\]\] responsibility passed to use()**

}

类型安全与资源安全

• 对每个对象的访问，均遵循其定义时的类型（类型安全）

• 每个对象都能被正确地构造与销毁（资源安全）

• 通过指针进行的每一次访问，所指向的要么是有效对象，要么是 \`nullptr\`（内存安全）

• 通过指针进行的访问，不会指向 \`nullptr\`（通常通过运行时检查来保证）

• 通过带下标的指针进行的访问，其索引均在合法范围内（通常通过运行时检查来保证）

构成安全违规的情形

• 逻辑错误：语法完全合法但未体现程序员意图的代码结构，例如本应使用 \`&lt;=\` 或 \`&gt;\` 的地方却使用了 \`<\`。

• 资源泄漏：未能释放资源（如内存、文件句柄和锁），可能导致程序因资源耗尽而陷入停滞。

• 并发错误：未能正确处理并发活动，从而导致（通常难以排查的）问题，如数据竞争和死锁。

• 内存损坏：例如，由越界错误引起，或通过指向已不存在对象的指针访问内存，进而修改了另一个对象。

• 类型错误：例如，使用不当类型转换的结果，或通过与写入时不同的成员来访问联合体（union）。

• 溢出与意外转换：例如，无符号整数循环变量发生意外的回绕（wraparound），或发生了缩窄转换（narrowing conversion）。

• 时序错误：例如，向本应在 1 毫秒内响应外部事件的设备交付结果时，耗时却达到了 1.2 毫秒。

• 终止错误：在不允许无条件终止的程序中，使用了会在遇到"意外情况"时终止运行的库。

标准初始考虑的配置文件集

• 算法 – 所有范围，禁止对 \`end()\` 进行解引用

• 算术 – 捕获溢出和下溢，捕获隐式窄化转换

• 类型转换 – 禁止类型转换

• 并发 – 消除死锁和数据竞争（硬性要求）

• 初始化 – 每个对象都必须初始化

• 失效 – 禁止通过失效指针访问（包括悬空指针）

• 指针 – 禁止对内置指针进行下标操作（使用 \`span\`、\`vector\`、\`string\` 等）

• 范围 – 捕获范围错误

• RAII – 句柄拥有的每个资源

• 类型 – 初始化、范围、类型转换、失效、指针

• 联合类型 – 禁止使用联合类型（使用 \`variant\` 等）

• 必须显式请求配置文件，并且在不适用的情况下可以抑制。
