[协程核心原理](https://lewissbaker.github.io/)

* 编译器生成状态机，将[协程转换为switch-case结构](https://lewissbaker.github.io/2022/08/27/understanding-the-compiler-transform)。使其能够在函数内的特定点暂停执行，然后再恢复执行。
* 协程的激活帧activation frame视为由两部分组成：
  1. 协程帧coroutine frame：（可以分配在堆上）保存了协程在挂起时持续存在的部分激活帧，如：局部变量、挂起点等。
  2. 栈帧stack frame（栈上分配）：部分仅在协程执行时存在，并在协程挂起并将执行权转回调用者/恢复者时被释放。
* Promise类型控制行为，决定初始/最终挂起、返回值等
* Awaitable对象管理挂起/恢复，提供异步操作接口

三大核心组件：

* **Promise**对象：协程的“控制中心”，决定其开始、结束、返回值及异常处理行为。
* 协程句柄 (std::**coroutine\_handle**)：用于从外部手动恢复或销毁一个已暂停的协程。
* **Awaitable**对象：co\_await 右侧的对象，决定等待时的具体行为（如是否立即恢复、如何挂起）。


|                | **线程**                                                                                                                                                                                                                                                   | **无栈协程**                                                                                                                                                                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **任务模型**   | **抢占式**多任务：<br/>由**操作系统**（而非程序员）**控制**任务切换的时机，可以/可能在任何时间点（如：时间片用尽、更高优先级任务就绪时）中断（依赖硬件支持，如定时器中断）当前任务，转而执行其他任务。                                                     | **协作式**多任务：<br/>**任务主动让出**控制权（程序中显式co\_await co\_yield让出，否则的话会一直运行），只有在当前任务自愿放弃CPU时，其他任务才能执行。（无需硬件中断，实现简单）。                                                                                     |
| **创建销毁**   | 线程独立栈空间（每个线程约**MB**级栈空间）<br/>（部分场景）限制单个进程中的总线程数在\**~~百到~~千\**<br/>创建（**ms级别**）/销毁线程成本高，最好通过**线程池复用**。                                                                                      | 堆上（除非优化到栈上分配）分配协程帧（**KB**级别且动态增长）<br/>单进程可**百万**级协程<br/>创建（**ns级别**）/销毁成本极低，可动态创建大量短期任务。                                                                                                                   |
| **上下文切换** | 高开销。<br/>上下文切换需**用户态-内核态切换**，<br/>需保存**完整的CPU状态**（完整寄存器+栈指针）<br/>线程的创建、销毁和切换都需要进入内核态，开销较大。                                                                                                   | 低开销。<br/>协程切换本质是函数调用。<br/>协程的创建、销毁、上下文切换无需切换内核态（**纯用户态**）。<br/>仅保存最小必要状态（挂起点局部变量）。                                                                                                                       |
| **缓存友好性** | 差。<br/>每次线程切换导致如下：<br/>1. L1/L2/L3缓存全部失效（非优化场景：不同线程访问不同内存区域）<br/>2. TLB（地址转换缓存）（局部）刷新/失效；分支预测器历史清空<br/>3、（当数据布局在不显式执行缓存行对齐、填充、数据分离等优化时）伪共享/FalseSharing | 好。<br/>连续执行相似任务（可能访问相似内存区域），缓存热度高&命中率高。<br/>1、协程B复用A的CPU缓存， L1/L2/L3缓存保持热度。<br/>2、无TLB抖动（协程不切换地址空间，共享代码和数据页）<br/>3、**较少伪共享**（不同协程帧在堆上独立分配、内存地址较远，一般不共享缓存行） |
| **同步**       | 线程同步原语（锁、条件变量、原子类型等），编程复杂度高。<br/>需考虑适当颗粒度的加锁解锁，规避死锁等。                                                                                                                                                      | co\_await、co\_yield等关键字进行挂起和恢复，编程复杂度低。<br/>（无需锁、条件变量等，因为不会在临界区被中断，天然无竞争条件）                                                                                                                                           |
| **代码风格**   | 回调/异步（**回调地狱或复杂future链**）<br/>同步+多线程管理                                                                                                                                                                                                | 顺序编写，编译器转换为状态机（co\_await 嵌套自动组合）<br/>协程的同步代码风格比回调地狱或复杂并发原语更易维护                                                                                                                                                           |
| **适用场景**   | **CPU密集型**计算<br/>需要真正并行                                                                                                                                                                                                                         | **I/O密集型**高并发（如：需要大量并发I/O操作但每个任务执行时间短的场景）<br/>网络服务器<br/>异步任务链                                                                                                                                                                  |
